## Cambio de base de datos

Archivo local: `supabase/migrations/20261023185053_audit_memory_fields_and_trigger_access.sql`.

Aplicado a `yjnidbgjkobzlmhpzawz` con el nombre `audit_memory_fields_and_trigger_access`; el servicio registró la versión **20261023185729**. El historial remoto previo ya utiliza marcas distintas de varios archivos locales: no se debe ejecutar un push indiscriminado de las migraciones antiguas.

La corrección modifica exclusivamente la lista de campos del índice derivado, reconstruye los fragmentos de registros pertinentes y revoca permisos directos de dos funciones trigger. No cambia roles de miembros, RLS, contraseñas, fichas, adjuntos originales ni la biblioteca general de OpenAI. Se probaron dos aplicaciones consecutivas en una base aislada para comprobar su repetición segura.

La revisión de seguridad posterior no muestra tablas públicas sin RLS ni las dos funciones trigger accesibles anónimamente. Quedan avisos que requieren interpretación, no cambios automáticos indiscriminados:

- Las funciones RPC autenticadas que implementan permisos, miembros, archivos e integraciones son intencionales y validan la identidad dentro de la función; retirar todos sus permisos rompería la aplicación.
- Las tres tablas privadas sin políticas usan RLS para impedir el acceso directo; no se añadieron políticas que expusieran secretos o contadores.
- [Protección de contraseñas filtradas](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) desactivada. No se cambió configuración de Auth ni se contrató un plan.
- El asesor de rendimiento señala índices de claves foráneas y políticas evaluadas por fila. No se añadieron decenas de índices ni se eliminaron índices de memoria por figurar como poco usados sin evidencia de consultas lentas.

## Reproducción

```powershell
npm test
npm run typecheck
npm run build
npm run start -- --hostname 127.0.0.1 --port 3107
```

En otra terminal, con Playwright disponible y, si hace falta, su ruta explícita:

```powershell
$env:PLAYWRIGHT_MODULE_PATH = 'ruta/al/node_modules/que/contiene/playwright'
$env:TEST_BROWSER_PATH = 'ruta/al/chrome-headless-shell.exe'
node --import tsx --env-file=.env.local scripts/verify-flows.mjs
$env:TEST_APP_URL = 'http://127.0.0.1:3107'
node --env-file=.env.local scripts/verify-live.mjs
```

El primer script exige un destino local y bloquea todas las conexiones externas salvo las de Supabase, que responde él mismo con datos sintéticos. Los resultados se escriben en `.vercel/`, ignorado por Git. El segundo realiza peticiones reales de solo lectura y verifica los rechazos de acceso sin sesión. `scripts/verify-live-permissions.sql` comprueba la base real con claims temporales revertidos, sin iniciar sesión como otra persona.
